# FAA Decision Momentum Analysis Code

This repository contains the analysis notebook for the manuscript:

**Frontal Alpha Asymmetry and Satisfaction-Rating Changes Presentation: An Exploratory Instructed After Price Pilot Study**

This is a **code-only repository**. It provides the Python/Jupyter workflow used to run the EEG and behavioural analyses reported in the manuscript. It does **not** include raw data, de-identified feature data, product images, participant information, or any other study dataset.

## What the notebook does

The notebook implements the analysis pipeline used in the manuscript, including:

1. **EEG preprocessing workflow**
   - Loading EEG/session files from a local authorised data directory.
   - Filtering EEG data.
   - Applying ICA-based artefact correction.
   - Average re-referencing.
   - Extracting price-locked epochs.
   - Applying task-window artefact rejection.

2. **Feature extraction**
   - Computing post-price frontal alpha asymmetry, FAApost, from F3/F4 over 0–3 s after price onset.
   - Computing pre-price baseline FAA, FAApre, from −1 to 0 s.
   - Computing dFAA = FAApost − FAApre.
   - Computing centro-parietal posterior alpha power as a tonic arousal-related measure.
   - Computing selected sensitivity features such as alternative frontal-pair FAA measures.

3. **Behavioural variable construction**
   - Loading pre-price and post-price satisfaction ratings.
   - Computing rating shift, ∆ = Ratingpost − Ratingpre.
   - Creating Valence labels: Positive Shift and Negative Shift.
   - Computing Decision Momentum as |∆|.
   - Handling scale-boundary no-change trials according to the manuscript analysis plan.

4. **Statistical analysis**
   - Running the Core Decision–Momentum Model:

     ```text
     FAA ~ Valence × Momentum + RatingProduct + Session
     ```

   - Running GEE as the primary estimator.
   - Running cluster-robust OLS as a sensitivity estimator.
   - Running session-stratified models.
   - Running tonic/session analyses using FAApre, FAApost, dFAA, and posterior alpha.
   - Running robustness checks using mixed-effects models, participant-level permutation, item-level dependence checks, price-deviation covariates, participant sex covariates, alternative electrode pairs, rank coding, winsorisation, CSD, and individualized alpha bands.

5. **Single-trial classification**
   - Running logistic regression with Leave-One-Group-Out cross-validation grouped by participant.
   - Predicting Valence from FAA alone across Decision Momentum thresholds.
   - Reporting accuracy, balanced accuracy, ROC AUC, permutation p-values, participant counts, class counts, and single-class folds.

6. **Figure and table generation**
   - Producing manuscript tables and supplementary tables.
   - Generating the session-stratified hybrid CDM plot.
   - Generating the pooled supplementary CDM plot.
   - Exporting figure files for manuscript preparation.

## Running the notebook

Because no data are provided in this repository, the notebook will not run successfully until the required local study files are available and the file paths in the notebook are configured correctly.

A typical workflow is:

1. Clone the repository.
2. Place authorised study data in a local directory outside the public repository, or in a local ignored directory.
3. Update the path variables in the notebook to point to the local authorised data directory.
4. Install the required Python packages.
5. Run the notebook from top to bottom.
